# CLI 设计：aas（agent-assets-sync 的命令行形态）

> 状态：**设计稿 v4（开放问题清零；multi-lens-review 第 1–4 轮收敛——第 3、4 轮连续零新增 P0/P1；阶段 1 已落地）**（2026-09-28）
> 本文回答：命令有哪些、安装怎么记账、"换编辑器"怎么适配、分几步落地。
> 上一份设计（[design.md](design.md)）讲的是"为什么独立成项目 + 本地同步怎么做"；本文是它的续篇，讲"CLI 化 + 从远端安装"。

## 1. 目标（用户 2026-09-28 拍板的预期）

1. 命令名叫 **`aas`**，像 `aas add <源> <规则名>` 这样用——**源**是仓库地址，或在配置里登记过的短名（见 §5）。
2. 能**读取远端仓库里的所有规则**：把仓库克隆进本地缓存（§4），按用户的选择装进对应编辑器的目录。
3. **认得当前编辑器**（本机是 Trae CN）；认不出或命中多个就让用户选。
4. Trae 的命名麻烦（规则必须带 `rule-` 前缀）——**这项已实测完毕**，见 §3，不用重新调查。
5. **本地名和原名必须映射清楚**：否则将来查不了"是不是重复装过"、"该 update 哪个"、"该删哪个"。这是硬需求，§4 的账本就是为它设计的。

**不做什么**：往远端仓库推送/新建规则。源仓库的写入永远是"改文件 + git push"，aas 不管 git 提交。

## 2. 两种安装形态（并存，不打架）

| 形态 | 谁用 | 怎么生效 | 账记在哪 |
|---|---|---|---|
| **链接形态**（现状，保留） | 你自己的源仓库（retro-skills：rules/ 与 skills/） | 源文件 → 符号链接/junction → 运行时；改源即生效 | `sync.config.json`（映射表） |
| **安装形态**（本次新增） | 别人的远端仓库（git URL / 登记短名） | clone 进本地缓存 → 从缓存装进编辑器目录 | `~/.aas/installed.json`（账本，§4） |

**为什么安装形态不直接复制完事，还要缓存**：两个理由。

- **一套机制**：如果远端装的是"真实副本"、本地装的是"链接"，同一个运行时目录里就有两套机制——这正是架构文档 §9 V3 用血泪验证过的坑（`npx skills add` 把链接换成副本，当时查了半天）。缓存 + 链接让**所有运行时条目都是链接**，体检逻辑几乎不用改。
- **一次下载、多编辑器复用**：同一条规则可以装进 Trae、也可以装进将来的 Claude Code / Cursor——都从同一份缓存链接过去。更新时刷新一次缓存，各编辑器重新对账即可。

> **安装形态默认 link（缓存 + 链接），2026-09-28 用户拍板**；`--copy` 作例外阀（比如你就是要脱离缓存独立存在）。

**公理的修订**：原来架构文档 §4 说"运行时目录只读"。CLI 化后修订为——**运行时目录禁止人手改；一切写入都经工具（sync 建链接 / aas 装条目），且留账**。人手改仍然是被禁止的，这条不变。

## 3. 编辑器适配器（editor adapter）

每个编辑器一个适配条目，说清四件事：目录在哪、东西叫什么名、是文件还是目录、有什么前置条件。

```jsonc
// sync.config.json 演进后的形状（现有两个 targets 归入 trae-cn 适配器）
{
  "editors": {
    "trae-cn": {
      "detect": ["~/.trae-cn"],           // 检测信号：目录存在即认
      "prereq": "windows-dev-mode:rules", // 规则侧 file symlink 依赖开发者模式
      "rules":  { "dir": "~/.trae-cn/user_rules", "nameTemplate": "rule-{name}", "level": "file",  "frontmatter": false },
      "skills": { "dir": "~/.trae-cn/skills",     "nameTemplate": "{name}",       "level": "dir" }
    }
  },
  "sources": {},                            // 源登记：短名 → 仓库地址（aas add 的第一个参数；当前无登记）
  "linkTargets": [ /* 现有两个 target 原样保留，各加一个 "editor": "trae-cn" 字段 */ ]
}
```

**配置文件的演进纪律**：文件顶部加 `"schemaVersion": 1`；载入器**必须兼容旧格式**（只有 `targets`、没有 `editors`/`sources` 的旧配置 → 视为仅链接形态，照常工作）——阶段 2 落地，配单测。

**Trae CN 的命名结论（2026-09-28 已实测，直接引用，不再调查）**：

| 事实 | 出处 |
|---|---|
| 规则文件名**必须**是 `rule-<名字>.md`，缺前缀不加载 | 架构文档 §9 V1 |
| 全局规则**没有 frontmatter**，纯 markdown | 同上 |
| 技能装在 `~/.trae-cn/skills/<名>/`，目录名随意 | 同上 |
| 编辑器**跟随**符号链接 / junction 读取 | 架构文档 §9 V4 |

**断言边界（勿外推）**：「编辑器跟随链接」只在 Trae CN 实测过。**接入任何新编辑器前，必须先实测该编辑器是否跟随符号链接/junction**，再写它的适配器。

**其他编辑器（Claude Code / Cursor / …）**：适配器占位，**用到时再研究接入**（各自目录、命名、是否要 frontmatter 转换都不同，Cursor 的 `.mdc` 就带 frontmatter）。架构是配置驱动——加一个编辑器 = 加一段 JSON，不改代码（若需 frontmatter 转换，才加一小段适配代码）。

**检测规则**：把 `editors` 里 `detect` 命中的都列出来 → 恰好一个，就用它；多个或零个，交互让用户选（脚本模式必须 `--editor <名>` 显式指定，传不存在的名要报错并列出可选值）。

## 4. 账本：`~/.aas/` 的布局与 installed.json

```
~/.aas/
├── installed.json     账本：装了什么、从哪来、在哪些编辑器、叫什么名
├── repos/             缓存：键 = 来源+分支（git：`<owner>/<repo>`，带 `#分支` 安装的为 `<owner>/<repo>@<分支>`；
│                       本地目录：`local-<目录名>-<路径短哈希>`——不同目录同名文件夹不共用缓存）
├── temp/              安装过程的临时区（用完即清）
└── installed.json.bak 账本上一次写入前的备份（每次写前滚动）
```

**installed.json 形状**（一条 = 一个资产 × 一个编辑器）：

```jsonc
{
  "schemaVersion": 1,
  "entries": [
    {
      "id": "code-style",                    // 资产唯一名（判重/更新/删除的主键）
      "kind": "rule",                        // rule | skill（生成规则见下）
      "status": "installed",                 // installing | installed（半装态恢复用）
      "editor": "trae-cn",
      "originalName": "code-style.md",       // 远端仓库里的原名
      "runtimeName": "rule-code-style.md",   // 编辑器目录里的名（映射！）
      "runtimePath": "~/.trae-cn/user_rules/rule-code-style.md",
      "mode": "link",                        // link | copy
      "source": {
        "repo": "https://github.com/<owner>/<repo>",
        "ref": "main",
        "commit": "abc1234",
        "path": "rules/code-style.md",       // 仓库内的相对路径
        "fetchedAt": "2026-09-28T16:00:00+08:00"
      },
      "installedAt": "2026-09-28T16:05:00+08:00"
    }
  ]
}
```

**id / kind 的生成规则**（评审 P1-1 补）：

- 目录且含 `SKILL.md` → `kind: skill`，`id` = 目录名；`.md` 文件 → `kind: rule`，`id` = 文件名去扩展名。
- 同一次 add 里 id 撞车（仓库内同名）→ 报错并列出候选路径，用 `--as <id>` 指定。
- `runtimeName` 由编辑器适配器的 `nameTemplate` 从 `originalName` 算出。

**这份账本直接回答用户点名的三个问题**：

- **重复添加？** `add` 前先查 `(id, editor)`——已存在就问：跳过 / 覆盖 / 取消；再查**链接形态的想要名单**（`linkTargets` × `nameTemplate` 算出的运行时名）是否占用同一个 `runtimeName`——占用则拒绝，提示先手工移除该链接或用 `--as` 换 id；**再做大小写不敏感撞名检查**（Windows 文件系统大小写不敏感，`Code-Style` 与 `code-style` 会落到同一个文件）。
- **update 哪个？** `update` 按账本逐条刷新：重新拉源 → 比对 commit → 换缓存 → 校验链接仍指对。
- **删除哪个？** `remove` 按账本精确定位运行时条目，摘掉并销账；`--purge` 连缓存一起清。

**账本的写入纪律（评审 P1-3/P1-4 补）**：

- **原子写**：写临时文件 → 原子改名覆盖（仓库里 migrate 已有同款模式）；写前把当前账本滚动为 `.bak`。**缓存 clone 同款纪律**：clone 到 `temp/` → 完整后原子改名进 `repos/`，目标已存在则先删旧再挪（或复用），杜绝半截仓库。
- **半装态**：add 的顺序是 **先记账（`status: installing`）→ 写运行时 → 改 `installed`**。任何一步崩溃，doctor 都能对账：installing 且运行时在 → 补置 installed；installing 且运行时不在 → 提示重跑 add（幂等）。remove 则相反：**先摘运行时 → 后销账**，中断重跑即可收敛。
- **读取容错**：剥 BOM + schema 校验；损坏 → 报错并指路 `.bak`，**禁止静默当空账本**。
- **快照语义**：`runtimeName` 等字段是**装的那一刻的快照**——之后改编辑器的 `nameTemplate`，旧条目不追改（想改就 remove 后重装）。
- **并发**（v1 界限）：原子替换 + `.bak` 保证单次写不损坏；**跨进程锁 v1 不做**（与错题集 KB 挂账的"并发写保护"（架构文档 §10 H4）同族，挂候选：信号 = 真发生一次并发冲突）。

## 5. 命令清单与安全边界

**约定**：`<源>` = git URL 或 `sources` 里登记的短名（剥 `.git` 后缀；支持 `仓库#分支` 指定 ref；本地路径也认）。所有命令退出码统一 **0 = 成功/一致，1 = 有差异/未命中，2 = 出错**；错误信息必须带可执行的下一步。

| 命令 | 干什么 | 会写什么 |
|---|---|---|
| `aas`（无参）/ `aas doctor` | 体检：链接形态 + 安装形态一起查，报差异（详见 §6） | 只读 |
| `aas sync [--replace] [--rm-old]` | 链接形态同步（就是现在的 `--apply` 改子命令） | 只建缺失的链接；删类动作仍要显式 flag；**碰到账本条目不删，提示走 aas remove（见 §6）** |
| `aas list [--editor <名>]` | 列出：登记的源、缓存里的仓库、装了什么、从哪来 | 只读 |
| `aas add <源> [名…]` | clone（一次性拉进缓存，**不等于全装**）→ 列出该源的规则/技能 → 装进编辑器 → 记账。**不给名则交互多选，列表里已装/未装直接标注（数据源=账本 `(id,editor)`）**；**非 TTY → 报错提示给名** | 写缓存 + 运行时 + 账本；`(id,editor)` 已存在：TTY 问跳过/覆盖/取消，**非 TTY 默认跳过并打印（要覆盖必须显式 `--yes`）**；与链接形态撞名 → 拒绝 |
| `aas update [名] [--all]` | 按账本刷新已装条目；也是**缓存漂移的修复入口** | 缓存 + 运行时 + 账本 |
| `aas remove <名> [--editor <名>] [--purge]` | 摘运行时条目 + 销账；`--purge` 连缓存 | 会删东西：TTY 交互确认；**非 TTY 没给 `--yes` → 直接报错退出**（绝不静默删） |
| `aas import <名>` | 把编辑器里**手建**的规则收进你自己的源仓库（链接形态接管） | 写源仓库；**只写源，不自动建链接**——装完提示跑 `aas sync`；**源里同名 → 拒绝**（提示先处理同名或换名） |
| `aas editors` | 列出检测到的编辑器与各自目录、前置条件 | 只读 |
| `aas config get` | 打印用户配置字段（带中文解释；交互下可直接选择修改） | 只读（交互下修改会写 `~/.aas/config.json`） |
| `aas config set <键> [值]` | 设置用户配置：repoRoot 弹文件夹选择器、editor 弹单选列表；给值直接写 | 写 `~/.aas/config.json` |
| `aas config init` | 初始化向导：按 repoRoot → editor 顺序设置（已设置的显示当前值问是否要改） | 写 `~/.aas/config.json` |

**配置分层（2026-10-10）**：机器相关的路径不再写进 `sync.config.json`（随包骨架），改放 `~/.aas/config.json`（`repoRoot` + `editor`）。`repoRoot` 定了，链接形态的相对 `srcDir` 与技能 `localPath` 都自动推导；优先级：**环境变量 > 用户配置 > 骨架**。详见 [design.md](design.md)「配置分层」。

**链接形态条目的移除**不走 `aas remove`（它只管账本）：手工删运行时链接即可（架构文档 §8.1 已有回滚说明），doctor 会如实报缺失。

## 6. 体检整合（防两套机制打架——本设计最容易翻车的地方）

现状：体检把"不在映射表里"的一律报"孤儿"、把"真实副本"报"需替换"。CLI 化后运行时里会多出**账本管的条目**，体检必须认识它们。

**规则（账本优先，全类豁免）**：体检对每个运行时条目**先查账本**——能对上 `(id, editor, runtimeName)` 的，一律归入新类「aas 安装」，**在 ok/needLink/wrong/legacy/staleSelf/orphans 全部六类之前拦截**。这样保证：

- 不会被当孤儿误报；
- 不会被 `--replace` 当"真实副本/指错的链接"删掉；
- 不会被 `--rm-old` 当"旧名残留（内容指纹撞车）"**不可逆删除**——这是第 1 轮评审抓出的最危险序列：aas 以 `--copy` 装了一条与本地源同内容的规则 → `sync --rm-old` 的 legacy 分类按内容指纹匹配 → 删除。账本拦截后此路径关闭。

**aas 条目自己的三态漂移体检**（对账本条目也逐一核）：

| 漂移 | 表现 | 修复入口 |
|---|---|---|
| 断链 | 缓存被删/被移，链接目标不存在 | `aas update <id>`（重 clone + 重建链接） |
| 副本化 | 账本记 `link`，运行时已是真实副本（外部工具干的） | `aas update <id>` 重置 |
| 指向别处 | 链接指向缓存之外的路径 | 同上 |

报告里加一行 `aas 安装 N`，取数即账本条数——**数字只留这一处**。

## 7. 交互与依赖

- **默认安静，删东西才开口**：`add`/`update`/`sync` 静默执行（好写脚本），结束时**打印一行变更摘要**（装/改/删了什么、账本在哪）；`remove`、`--replace`、覆盖已存在条目时，终端里 y/n 确认，`--yes` 跳过。问询用 Node 自带 readline 就够；**多选列表**才用第三方库。
  > **Spike 实测（2026-09-28，阶段 1）**：非交互管道下 inquirer 的 confirm **不会自保护**——管道输入会按默认值静默放行（实测：管道一行空输入 → confirm 直接按默认 Yes 通过）。
  >
  > **由此定下交互总闸（评审第 2 轮补，覆盖同族）**：**一切交互问询（y/n / 单选 / 多选）之前先判 `process.stdin.isTTY`**；非 TTY 且缺必需输入（`--editor`、规则名等）→ **报错退出**，把 prompt 交给管道等于把决定权交给运气。非 TTY 的缺省取向分两档：**危险操作（remove）没 `--yes` → 报错**；**add 撞已存在条目 → 默认跳过并打印**（覆盖必须显式 `--yes`）——宁可少装，不可静默覆盖。
- **放开零依赖约束（用户 2026-09-28 拍板）**：引入 **commander**（参数与子命令）+ **@inquirer/prompts**（列表选择 / y/n），其余保持 Node 内置。**spike 已完成（2026-09-28，随阶段 1）**：模拟按键驱动实测中文消息/选项渲染、方向键选中、回车确认全链路通过；附带发现非 TTY 静默放行问题（见上条）。落地时同步改架构文档 §8.1 前置条件第 4 条。

## 8. 前置条件清单（换机器时照这个核；评审 P1-6 补）

1. **git** 在 PATH（clone 用；私有仓库需凭证已配好）
2. **Node ≥ 20**（commander / @inquirer 的 engines 要求；`package.json` 写 engines 字段）
3. **npm**（两条本地全局安装路径，**均已实测**（2026-09-28）：
   - **开发态**：`npm link` —— 活链（junction 指向仓库），改代码立即生效；仓库不能挪/删
   - **本地全局装**：`npm run localg`（= `npm install -g .`）—— 实测在本机 npm 上同样落成 junction 活链；`package.json` 的 `files` 白名单保证只装 `src/` + `sync.config.json` + `docs/`（默认配置文件漏装即废，已用 `npm pack --dry-run` 核过包内容）；卸载 = `npm run localg:rm`
   - **从 GitHub 装**（推上去后 `npm install -g github:SeedHuang/agent-assets-sync`）理论可用，未实测——`private: true` 只挡 npm 仓库的 publish，不挡 git 装；发 npm 仓库另见 R31
   - PowerShell 执行策略拦 `.ps1` shim 时，同名 `.cmd` 兜底）
4. **网络可达仓库托管点**（GitHub 等；代理自备）
5. **Windows 开发者模式**——**规则侧 file symlink 依赖它**（技能 junction 不需要）；写在 trae-cn 适配器的 `prereq` 字段里，接入新编辑器时逐个查明并标注
